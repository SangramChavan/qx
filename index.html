Scan it. See what it is. Ask about it.

QX is a round QR code. Any phone camera opens its page in the browser, which shows what it is attached to (a product, business, person, machine or asset) with the right information and buttons, and lets you ask questions answered from that item’s own information. No app, no sign-up. Behind it, rings carry the time, an optional GPS position and a serial number that survive scratches.

What happens when you scan

No app, no sign-up, no setup. Scan it like any QR code.

  1. Your ordinary phone camera reads the code and opens the QX in the browser.
  2. The page shows what the code belongs to, with the information and buttons that fit it: call, directions, support, save contact, report a fault.
  3. Type a question if you need to. The answer is quoted from that item’s own information, and it tells you when the answer isn’t there.
  4. That’s it. The web address printed in the code never changes, even when the information behind it does.

How a QX symbol is built

Three layers, each doing one job.

1. QR core: works everywhere

A standard ISO/IEC 18004 QR code (error-correction level M, 4-module quiet zone). Any phone camera reads it and opens your link. Up to 106 bytes of URL.

2. Time marks

48 marks between the core and the rings encode the date and time to the second, with an 8-bit checksum, so a printed symbol records when it was made.

3. Data rings

152 bytes: 104 of payload (time, optional GPS to about 1–2 m, a serial, and an optional 64-byte Ed25519 signature) and 48 of Reed–Solomon error correction that repairs up to 24 damaged bytes.

Where it fits

  • Product authentication: a signed link on a label tells buyers the unit is genuine, and the issuer can see repeat scans.
  • Asset tags and inventory: serial, commissioning time and place, readable offline once a reader exists.
  • NFC + QR tags (pet, luggage, accessories): a printed fallback next to a tap-to-read chip.
  • Event tickets: a live on-screen code whose timestamp changes every second, so screenshots go stale.

Make your own

Each QX page is one small JSON file in the open-source repo: a type, a title, facts, steps, FAQs and buttons. Add a file, run the build, and the page is live at a fixed address. Print that address as a QX from the studio below. Editing the file later changes the page, not the code on the label.

What QX does not do yet

  • Every QX page is public and static: no private information, no owner sign-in, and no scan analytics yet. Anything added to the repo is published, and stays in its history.
  • The ask box finds and quotes passages from the page’s own information. It does not write new answers or reason, so it can miss a question phrased very differently, and it says so instead of guessing.
  • Phone cameras read only the QR core. Reading the rings needs a QX reader, which is still in development, so signed verification today runs through the link in the QR code.
  • Tested with software decoders, not yet scanned from printed labels. Plan for at least 300 DPI printing: the smallest QR squares are 0.23–0.34 mm.
  • A signature shows who issued a code, not that a label is the original. A photocopy of a valid code still verifies, so copy detection needs server-side scan checks or a chip.

This is a draft specification and a working prototype, not a certified standard. Do not rely on it for safety-critical use.
